我不太相信「先做个 demo 再说」。
我更在意一个东西真正跑起来之后的样子：
别人能不能用、出错时会不会安静地错。

所以做校园助手的时候，我没有停在「能查空教室」这一步。我把它接进了飞书， 让它在群里真的能被 @ 到；把它挂在计划任务上，开机就在； 把每个接口对着官方 schema 一个个验过去，而不是看它返回了 200 就当成功。

这套东西现在的状态是：能用，但没做完。下面第三节我把它没做完的部分也写出来了—— 因为「知道哪里还没做」本身，比「做完了」更接近真实。

还没做完的

Unfinished

下面这几处，我不会在答辩里吹

WIP
  • 01 /绑定 现在是一个诚实的拒绝。官方的 Device Auth 端点已经定位到了， 但多用户隔离要靠按 open_id 切配置目录，还没接上。所以 /成绩、 /课表 现在拿不到个人数据。
  • 02 自然语言还没接。「今天有空教室吗」这种话它还听不懂， 只有 /命令 能用。接一个模型就能解决，但我想先把数据层弄干净。
  • 03 图书馆实时在座率没有官方数据。只有座位总量，算不出使用率， 所以这一版我直接把进度条砍了——而不是用一个编出来的数字填上去。
  • 04 个人接口的返回字段还没校准。需要拿到一个真实 PAT 才能核对。
04

我会什么

Stack
/ 01

接第三方 API

读官方文档、抓真实请求、对 schema 验字段。不是「能拿到数据就行」， 是「知道它为什么长这样」。

/ 02

让东西一直在跑

长连接不用公网 IP，计划任务开机自启，日志落在本地， 出错时人能看到——而不是第二天才发现昨晚就挂了。

/ 03

把边界划清楚

管理面板只听本机、凭据按请求传、做不到的功能明确拒绝。 大多数事故不是功能少，是边界糊。

/ 04

和 AI 一起做

AI 写代码，我定目标和验收标准。判断哪一版更好、哪里还不对， 这部分它替不了我。
